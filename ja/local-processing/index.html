LOCAL PROCESSING

本当にアップロードされないのか

選択したファイルはブラウザのFileオブジェクトとして読み取り、変換サーバーへ送らず、そのタブ内で処理します。

最終更新：2026年10月2日

ファイルを選んだ後の流れ

  1. 利用者が選択またはドロップしたファイルだけに、ブラウザがページからの読み取りを許可します。
  2. JavaScriptがFile／Blobとして内容を読み取ります。
  3. ページ、Web Worker、同梱したWebAssemblyのいずれかで処理します。
  4. 結果をBlob URLとして生成し、ダウンロードまたは作業トレイへ保存します。

通信されるもの

ページ、JavaScript、CSS、設定されたフォント、同梱Worker／Wasm、機械可読なツール台帳は通常のWeb通信で取得します。ツールは変換用サーバーAPIを使用しないため、入力・出力ファイルの中身をSHIAGENTの変換サーバーへPOSTしません。

一般的なWebサイトと同様、配信サーバーにはIPアドレス、時刻、ブラウザ情報、要求URL等のアクセスログが残る場合があります。詳しくはプライバシーポリシーをご覧ください。

作業トレイの保存場所

画像・SVG作業トレイとPDF作業トレイは、ブラウザ内のIndexedDBにFile／Blobを保存します。言語やカスタムワークフロー設定にはlocalStorageを使います。画面上でトレイを消去するか、ブラウザ設定からSHIAGENTのサイトデータを削除できます。

自分で確認する方法

  1. ブラウザの開発者ツールでNetworkを開きます。
  2. 一覧を消去し、テスト用ファイルを処理します。
  3. Fetch/XHRで絞り込み、選択ファイルを含む通信がないことを確認します。
  4. Application／StorageからIndexedDBのローカル保存を確認できます。

ブラウザ拡張、企業プロキシ、第三者が改変した配信環境はSHIAGENTの管理外です。利用中のドメインとHTTPS証明書も確認してください。
